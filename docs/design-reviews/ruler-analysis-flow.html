From “analyze these rulers” to eight calibrated scores each

This page maps the current executable path for a year-specific ruler cohort. It separates orchestration code, durable data, agent directives, and methodology—so we can review each layer without confusing the 80 evidence lenses with 80 final scores.

8 chapters10 lenses per chapter1 dossier per ruler-period1 judge per chapter and cohort8 scores per rulerClick a file to inspect it here
The central design choice. Evidence collection is ruler-centric: one persistent researcher builds a reusable ledger across 1B–8B. Scoring is chapter-centric: each judge sees one chapter across the entire cohort and applies one comparative meter. The ten lenses organize evidence; they are not separately scored and averaged.

7

No-search review loop, then strict formatting

A separate evidence reviewer examines every selected chapter without doing research or scoring. Recoverable gaps return to the same researcher thread for up to three rounds. After pass or credible saturation, a separate no-search formatter converts the permissive notebook into the validated dossier schema.

9

Judge one chapter across the full cohort

Each no-search judge owns one chapter and all eligible rulers. It reads the exact guide, establishes high/middle/low/edge anchors, reviews ten lenses per ruler, compares adjacent cases, and emits one half-point chapter score—or a justified null—plus confidence and calibration evidence.

Comprehensive implementation and directive inventory

This is the authoritative file index for the current review. It includes the active path, supporting infrastructure, directives, persistence, focused tests, and adjacent legacy surfaces that could affect or confuse the design. “Mandatory” means the present contract or normal execution fails without it; it does not mean the file can never be refactored.

Status rubric. Mandatory: required for correctness, execution, or the normative scientific contract. Important: material support, verification, observability, or explanation. Nice-to-have: useful convenience or non-critical documentation. Might-be-redundant: overlaps the active path or appears to be a superseded surface worth consolidation review. Might-be-too-much: valuable history or narrow infrastructure whose maintenance cost may exceed its current role.

Design-review notes for our next pass

These are the first seams worth inspecting together when we deepen this document.

Clear strengths

  • The run topology avoids X × 80 duplicated research passes.
  • Identity, citations, periods and job ownership have hard validation boundaries.
  • Evidence is reusable many-to-many and separates research from judgment.
  • Comparative chapter judging gives every ruler a shared meter.
  • Missing evidence affects confidence and nullability, not ruler quality by default.

Open review points

review gap The methodology requires a final score/order auditor, but the current research package does not expose an equally obvious dedicated auditor worker/planner/store seam. We should verify whether this is manual review only or incomplete automation.

review gap “X rulers” is operationally represented by a hand-authored/frozen manifest or all eligible cases; cohort selection policy itself deserves a clearer product-level interface.

next depth Add concrete schemas, table columns, artifact directory examples, prompt excerpts, failure/recovery state diagrams, and one end-to-end worked ruler.

viewer refinement — noted, not implemented Default every top-level JSON item to collapsed. As we understand each artifact, add file-aware semantic views rather than relying only on a generic JSON tree. For local-priors.json, present each top-level item explicitly as one evidence lens, show its lens/question identity in the collapsed heading, and emphasize the facts found when expanded. The current generic viewer remains accepted for this priors review.
